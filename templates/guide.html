Start here. Linux Guardian watches this computer, explains unusual behaviour, and only proposes a repair. You always approve a change.
The simple flow

1 · Monitor

Dashboard shows CPU, memory, disk, network and services. Green means the check passed; amber means watch it; red means it failed.

2 · Investigate

An incident is a grouped problem. Press Investigate to collect read-only evidence and see facts, an explanation, and a recommendation.

3 · Decide

Propose a fix only creates a preview. Nothing changes until you deliberately press Approve and run.

4 · Verify

After an approved repair, Guardian measures again. It marks the incident resolved only when the new reading proves the result.

Typing a request in plain English

The Assistant turns an ordinary sentence into one approved Linux command. It never invents a command: it matches your words against a fixed list of 14 actions, and anything not on that list simply cannot happen.

You typeLinux runs
how full is my disklinux/system.sh
is apache2 runninglinux/services.sh
create a file called noteslinux/workspace.sh create notes
restart apache2linux/healing.sh apache2

The last two change something, so they show you a preview and wait for a second, deliberate confirmation. If Guardian is not sure which action you meant, it asks instead of guessing — it never picks for you.

Important words

Incident

One real-world problem, not every individual metric. For example, high load and low CPU idle time become one CPU saturation incident.

Investigation

A read-only check. It collects evidence but cannot restart, stop, delete, or edit anything.

Daemon

An optional background loop. Every 30 seconds it records a small sample and can restart only the explicitly allowed service.

Approval

Your second confirmation before a write action. It is intentionally separate from the preview.
