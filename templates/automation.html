The daemon

What it does

The daemon is an optional background worker. Every {{ settings.DAEMON_INTERVAL or '30' }} seconds it does this: record a small health sample → check the allowed service → restart it only if it is down.

You do not need the daemon to use the dashboard. Turn it on only when you want Guardian to keep collecting history and watch the approved service while the web page is closed.

Recording history is helpful but never more important than recovery: if the database is unavailable, Guardian logs that problem and continues checking the permitted service.

I understand — show the four installation commands

Run these once in a terminal. They install the service, let systemd discover it, start it now, and then show its live log.

sudo install -m 0644 systemd/linux-guardian.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now linux-guardian
journalctl -u linux-guardian -f

For a short demo, run ./linux/guardian-daemon.sh in a terminal and press Ctrl-C when finished. It is not installed by default.

Scheduled tasks

systemd user timers, never root cron. A user unit needs no sudo, runs as this user, and can only touch files this user could already touch. A root crontab entry would mean the web application could schedule work as root — the exact privilege escalation the whole safety model exists to prevent.
